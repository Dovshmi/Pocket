# Pocket v1.41 — Adaptive Window (development branch)

Pocket's three permanent work layouts (Mini, Normal, Dashboard) now share a
resizable borderless window. **Extra Mini remains a separately enabled,
fixed-size launcher** and is not selected by width.

## Behavior

- Resize from a side or corner; the bottom-right corner is visibly marked.
- The current monitor work area, including its negative coordinates, limits
  geometry. Smaller monitors impose proportionally smaller minimums.
- Layout is chosen on mouse release: width < 470 → Mini; width ≥ 470 → Normal;
  width ≥ 950 and height ≥ 600 → Dashboard.
- Size is saved in `window_size`, while old `window_positions` and
  `window_position` fields remain compatible. Invalid sizes are ignored.
- Selecting a display preset in Settings restores that preset's dimensions.
- The initial size is fitted to the current monitor each time Pocket opens.
- No clipboard, notes, commands or network operations are introduced.

## Acceptance checklist (Windows)

- Resize each side and four corners, including when Pocket is pinned.
- Cross Mini/Normal/Dashboard breakpoints from both directions and confirm the
  current tool's edits survive each switch.
- Test 100%, 125%, 150%, 200% Windows display scaling; move between monitors
  with different scale factors and negative-coordinate secondary monitors.
- Test 1366×768 and 1920×1080 screens, and work areas with taskbars on the side.
- Confirm Ctrl+Shift+* toggle, tray restore, drag-to-move, auto-hide and PIN.
- Confirm opening/closing Extra Mini restores the last resizable work size.
- Test Notes RichEdit, Command editor, scrolling, quick search, and drag/drop.
- Confirm legacy preferences load without data loss and corrupted dimensions
  do not cause an off-screen popup.

This is a development branch, **not** a published v1.41 release.
